Modèle d'accès — 7 niveaux + rôle spécial

Chaque membre porte un rôle qui détermine les modules visibles. Les niveaux sont cumulatifs : un niveau donné hérite des accès de tous les niveaux inférieurs. Le Directeur Général attribue les rôles depuis /admin/users. Un membre peut être Actif ou Inactif.

1
Employé
Accès de base : tableau de bord, comptes rendus, documents, commandes techniciens.
2
Chef d'équipe
Mêmes accès qu'un employé, plus la supervision d'équipe.
3
Comptable
Accès élargi : registre RH, commandes médicales, statistiques & primes.
4
Directeur RH
Accès RH complet + gestion des primes et statistiques.
5
Directeur Administratif 1
Direction administrative : récapitulatif financier, validation des commandes techniciens.
6
Directeur Administratif 2
Direction administrative élargie, mêmes droits que DA1.
7
Directeur Général (Admin)
Accès total : gestion des membres, tous les modules, auditeurs externes.
★SPÉCIAL
Auditeur Externe
Accès restreint : tableau de bord + section Auditeurs Externes uniquement (données confidentielles).

Capacités transversales

Ces mécanismes reviennent dans plusieurs modules et forment le socle technique à reproduire.

Authentification déléguée

OAuth2 / OpenID Connect via un fournisseur externe (Hercules Auth), flux PKCE (S256), scopes openid profile email offline_access. Connexions Google, Apple, Microsoft ou code par e-mail (OTP). Protection anti-bot Cloudflare Turnstile.

Application installable (PWA)

Installable sur desktop et mobile, fonctionne comme une app native, mises à jour automatiques. Guide d'installation intégré pour Chrome/Edge, Android et iOS/Safari.

Extraction IA & OCR

Métadonnées de documents déduites automatiquement à l'upload. Import IA/OCR dans les statistiques : Excel, CSV, PDF, Word et photos convertis en lignes de tableau, à vérifier avant enregistrement.

Import / export tabulaire

Import et export CSV (commandes, statistiques) et Excel (audit). Comparaison automatique entre jeux de données successifs pour les commandes médicales.

Édition concurrente verrouillée

Le tableau financier pose un verrou d'édition (« Verrou actif / Libérer ») pour empêcher les écritures simultanées, complété d'un verrouillage mensuel des données clôturées.

Fenêtres temporelles & notifications

Les comptes rendus n'acceptent une soumission « dans les temps » que sur un créneau horaire des jours ouvrables ; toute soumission hors fenêtre est signalée aux superviseurs.

Confidentialité par rôle

Certaines données (primes des médecins externes) sont cloisonnées à un rôle spécial + le DG, indépendamment de la hiérarchie de niveaux classique.

API financière tierce

Une API expose les données financières consolidées à des systèmes externes (comptabilité, BI). Requêtes authentifiées par clé API avec restriction possible par adresse IP.

06

À reproduire pour votre plateforme

Les briques structurantes à concevoir en priorité si vous rebâtissez cette plateforme indépendamment de Hercules.

  • ARBAC à 7 niveaux cumulatifs + rôle spécial cloisonné. Le cœur du produit : une matrice route × niveau minimum, plus un rôle « auditeur » orthogonal qui voit un module que même les niveaux intermédiaires ne voient pas.
  • BWorkflow de compte rendu quotidien avec fenêtre horaire et scoring. Créneau de soumission, compte à rebours, points de présence, détection hors-fenêtre, vue superviseur agrégée.
  • CGrand livre financier journalier multi-comptes. Report du solde J-1, calculs dérivés, pièces justificatives, verrou d'édition concurrent et clôture mensuelle.
  • DMoteur de paie localisé (Cameroun). Récap mensuel + bulletins individuels au format légal : CNPS, IRPP, CAC, CFC, FNE, congés, et régimes SESAME / SOFINA / SGC.
  • ESaisie tabulaire assistée par IA/OCR. Import de photos et documents bureautiques vers des tableaux structurés, avec relecture humaine avant validation.
  • FGestion documentaire à catégorisation automatique + API de sortie. Store de documents avec métadonnées déduites, protection par code, et API financière à clé pour l'intégration tierce.
À noter. L'application porte un nom interne « Poitiers Coworking » distinct de l'identité publique « Polyclinique de Poitiers ». Des données de test / démonstration subsistent dans les comptes rendus et la liste des membres — à ne pas confondre avec le contenu métier réel lors de l'analyse.
